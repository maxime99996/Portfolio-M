Stage SIO1

FICHE DESCRIPTIVE :

Dates du stage :

  • Date début : 05/01/2026
  • Date fin : 13/02/2026

Entreprise : Institut National de l'Audiovisuel (INA)

  • Tuteur de stage : M.MOUNIR ABID

    • Présentation de l'entreprise/société :

    L'Institut National de l'Audiovisuel (INA) est un établissement public français chargé de la conservation, de la valorisation et de la diffusion du patrimoine audiovisuel national. Il gère plusieurs millions d'heures de contenus télévisés, radiophoniques et multimédias, tout en développant des solutions technologiques pour la gestion et l'exploitation de ces archives.

    Mon stage s'est déroulé au sein du service informatique, plus spécifiquement dans l'équipe responsable de la gestion et du monitoring de l'infrastructure des datacenters de l'INA.

    Missions & tâches réalisées :

    Pendant mes 6 semaines de stage, ma mission principale a consisté à développer un batch Java utilisant Spring Batch capable de lire et analyser automatiquement des fichiers Excel contenant des données de monitoring de PDU (Power Distribution Units) - des équipements de distribution électrique des datacenters.

    Objectifs du projet :

    • Automatiser le traitement de fichiers Excel historiques contenant des mesures électriques
    • Extraire les données (courant, puissance, tension, facteur de puissance) pour chaque PDU
    • Stocker ces données dans une base de données SQLite pour analyse ultérieure
    • Générer des rapports au format standardisé A01

    Chaque fichier Excel contient plusieurs feuilles de calcul, et chaque feuille regroupe les mesures de 4 PDU identifiés par leur emplacement (PDU 1.1, 1.2, 2.1, 2.2). Pour chaque PDU, les données suivantes sont enregistrées : adresse IP, courant (A), puissance apparente (W), facteur de puissance et tension (V).

    Déroulement du stage semaine par semaine :

    Semaine 1 : Prise en main et développement initial

    Objectif : Prise en main du projet existant et développement d'un batch Java capable de lire des fichiers Excel.

    Environnement technique :

    • Environnement : Ubuntu (WSL sur Windows)
    • Langage : Java 11
    • Gestionnaire de dépendances : Maven
    • Bibliothèque principale : Apache POI 5.2.3 pour la lecture de fichiers Excel

    Travaux réalisés :

    • Configuration de l'environnement de développement (Maven, Apache POI)
    • Création de la structure de projet Maven standard
    • Développement de la classe ExcelPDUReader.java avec les fonctionnalités suivantes :
      • Ouverture et lecture d'un fichier Excel (.xlsx)
      • Sélection d'un onglet spécifique (A01)
      • Analyse automatique des en-têtes pour comprendre la structure des données
      • Parcours des lignes de données et extraction des valeurs pour chaque PDU

    Difficultés rencontrées :

    • Problème 1 : Téléchargement des dépendances Maven avec des erreurs "Unexpected end of ZLIB input stream"
      Solution : Nettoyage du cache Maven (rm -rf ~/.m2/repository/) et utilisation de versions stables des plugins
    • Problème 2 : Chemin de fichier incorrect lors de la compilation
      Solution : Navigation vers la racine du projet et création du répertoire target/classes

    Résultats : Le programme a réussi à ouvrir le fichier Excel, lire l'onglet A01, détecter les en-têtes, identifier les 4 PDU et extraire les adresses IP et les données de mesure.

    Semaine 2 : Amélioration et structuration

    Objectif : Améliorer le code existant, corriger les bugs identifiés et structurer le projet de manière plus professionnelle.

    Travaux réalisés :

    • Refactoring du code pour une meilleure maintenabilité
    • Correction des bugs de lecture des colonnes Excel
    • Amélioration de la gestion des erreurs avec try-catch appropriés
    • Documentation du code avec commentaires JavaDoc
    • Optimisation des performances de lecture

    Compétences développées : Refactoring, clean code, documentation technique, optimisation de performances.

    Semaine 3 : Traitement multi-onglets

    Objectif : Étendre le batch pour traiter automatiquement tous les onglets d'un fichier Excel, et non plus un seul.

    Travaux réalisés :

    • Implémentation d'une boucle pour parcourir tous les onglets (sheets) du fichier Excel
    • Adaptation du code pour gérer des structures variables selon les onglets
    • Ajout de logs détaillés pour suivre la progression du traitement
    • Tests sur des fichiers complexes avec plusieurs dizaines d'onglets

    Résultats : Le batch est désormais capable de traiter de façon entièrement automatique des fichiers Excel très complexes comportant une multitude d'onglets.

    Compétences développées : Algorithmique (boucles imbriquées, gestion d'état), traitement de données complexes, logging et monitoring.

    Semaine 4 : Migration vers Spring Batch

    Objectif : Migrer le code vers le framework Spring Batch pour bénéficier de fonctionnalités avancées (restart, monitoring, transactions).

    Architecture Spring Batch implémentée :

    • Reader : ExcelPDUReader - Lecture lazy des fichiers Excel (un à la fois en mémoire)
    • Processor : MesurePDUProcessor - Transformation des données et enrichissement
    • Writer : FlatteningItemWriter - Écriture en base de données par lots
    • Configuration : BatchConfiguration - Orchestration du job avec chunks de 10

    Technologies utilisées :

    • Spring Boot 3.1.5
    • Spring Batch 5.x
    • SQLite (base de données)
    • Apache POI 5.2.3
    • SLF4J/Logback (logging)

    Travaux réalisés :

    • Création de la structure Spring Batch complète (Reader-Processor-Writer)
    • Implémentation du pattern ItemStreamReader pour le support du restart
    • Configuration des chunks (traitement par lots de 10 mesures)
    • Gestion des transactions avec PlatformTransactionManager
    • Création d'un listener (JobCompletionNotificationListener) pour les notifications de début/fin de job

    Compétences développées : Framework Spring Batch, architecture en couches, gestion des transactions, patterns de conception (Strategy, Template Method).

    Semaine 5 : Multi-fichiers et optimisations

    Objectif : Permettre au batch de traiter automatiquement tous les fichiers Excel d'un répertoire donné en argument.

    Travaux réalisés :

    1. Gestion des arguments en ligne de commande

    • Création de BatchArgumentsConfig pour récupérer le répertoire source via --batch.input.directory
    • Support de différents formats : argument CLI, variable d'environnement, application.properties
    • Gestion des chemins réseau Windows (UNC) et WSL

    2. Optimisation de la lecture Excel

    • Implémentation d'une lecture lazy (un seul fichier en mémoire à la fois) pour éviter les OutOfMemoryError
    • Tri alphabétique automatique des fichiers
    • Filtrage des fichiers temporaires Excel (~$*.xlsx)
    • Logs détaillés avec progression (fichier X/Y)
    • Extraction automatique de la date depuis le nom du fichier (format DDMMYYYY vers YYYY-MM-DD)

    3. Scripts d'automatisation

    • run-batch.sh : Menu interactif pour lancer le batch (répertoire local, réseau, personnalisé)
    • diagnose.sh : Diagnostic complet du projet (structure, dépendances, compilation)
    • test-config.sh : Vérification rapide de la configuration

    4. Documentation complète

    • README.md : Documentation générale du projet
    • GUIDE_UTILISATION.md : Guide d'utilisation détaillé avec exemples
    • TROUBLESHOOTING_MAVEN.md : Résolution des problèmes de compilation
    • application.properties.example : Exemple de configuration complète

    Difficultés rencontrées et solutions :

    • Mémoire : OutOfMemoryError avec chargement simultané de tous les fichiers
      Solution : Lecture lazy fichier par fichier
    • Réseau WSL : Chemins UNC Windows inaccessibles depuis Ubuntu
      Solution : Montage avec drvfs, script automatisé
    • Compilation Maven : Erreurs de packages et dépendances
      Solution : Version simplifiée de BatchArgumentsConfig sans @PostConstruct, diagnostic automatisé
    • Base de données : Tables manquantes (scan, pdu, oid_value)
      Solution : Création du schéma SQL complet avec toutes les colonnes nécessaires

    Résultats :

    • ✅ Traitement automatique réussi de 26 fichiers Excel
    • ✅ Gestion optimisée de la mémoire (un fichier à la fois)
    • ✅ Support du restart en cas d'interruption
    • ✅ Documentation professionnelle complète
    • ✅ Extraction correcte des dates depuis les noms de fichiers

    Compétences développées : Optimisation mémoire et performances, scripting shell (bash), gestion de projets complexes, documentation technique professionnelle, résolution de problèmes autonome, débogage avancé.

    Semaine 6 : Finalisation et professionnalisation

    Objectif : Finaliser le projet, corriger les derniers bugs, améliorer le schéma de base de données et préparer la livraison.

    Travaux réalisés :

    • Correction complète du schéma de base de données (ajout des colonnes manquantes : ip, nom_pdu dans table pdu)
    • Amélioration de la méthode creerScan() pour extraire automatiquement la date du nom de fichier
    • Correction du problème de type (Long vs Integer) dans les modèles OidValue et MesurePDU
    • Amélioration de la gestion des erreurs et des logs (messages plus clairs)
    • Tests finaux sur l'ensemble des 26 fichiers historiques du répertoire Bright
    • Versionning du code avec Git
    • Préparation de la documentation de livraison

    Résultats : Le projet est désormais stable, versionné et prêt pour une utilisation en production. Toutes les fonctionnalités demandées sont implémentées et testées avec succès.

    Compétences développées : Gestion de versions (Git), tests et validation, préparation à la mise en production, rigueur et qualité logicielle.

    Conclusion :

    Ce stage de 6 semaines à l'Institut National de l'Audiovisuel m'a permis de développer des compétences solides en développement Java et en particulier sur le framework Spring Batch. J'ai pu travailler sur un projet concret avec des contraintes réelles : performances, gestion mémoire, compatibilité multi-plateforme (Windows/Linux/WSL).

    L'expérience m'a également appris l'importance de la documentation, de l'autonomie dans la résolution de problèmes, et de la rigueur dans le développement logiciel professionnel. Le passage d'un simple script Java à une application Spring Batch complète, robuste et documentée m'a permis de comprendre les exigences d'un projet professionnel.

    Je remercie toute l'équipe de l'INA pour leur accueil et en particulier M. Mounir ABID pour son accompagnement, sa confiance et ses précieux conseils tout au long du stage.
