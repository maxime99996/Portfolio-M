Docker fête ses 12 ans : où en sont les conteneurs en 2025 ?

Publié le 21/11/2025 | Tags : Docker conteneurs DevOps cloud

Lancé en mars 2013, Docker a révolutionné la façon dont les développeurs livrent leurs applications. Douze ans plus tard, les conteneurs sont devenus le standard de facto du déploiement logiciel. Mais l'écosystème a considérablement évolué — et ce que Docker représente en 2025 va bien au-delà du simple outil de packaging.

Timeline — L'évolution des conteneurs (2013 → 2025)

13
Mars 2013
Naissance de Docker

Solomon Hykes présente Docker en open source à PyCon. Concept : "build once, run anywhere" grâce aux namespaces Linux.

17
2017
Kubernetes s'impose comme orchestrateur

Google open-source Kubernetes. La gestion de flottes de conteneurs à grande échelle devient possible et standardisée.

20
2020
Docker Desktop devient payant pour les entreprises

Changement de modèle économique — apparition d'alternatives libres : Podman, nerdctl, Rancher Desktop.

23
2023–2024
OCI et standardisation des images

L'Open Container Initiative impose un format universel. Les images Docker fonctionnent désormais sur n'importe quel runtime compatible (containerd, CRI-O…).

25
Novembre 2025
Docker 27 — build cache distribué et multi-plateforme natif

Docker 27 introduit un cache de build partagé entre membres d'une équipe et le build natif ARM/x86 sans émulation, accélérant drastiquement les pipelines CI/CD.

Techniquement, un conteneur Docker s'appuie sur deux primitives du noyau Linux : les namespaces (isolation des processus, réseau, fichiers) et les cgroups (limitation des ressources CPU/mémoire). Une image Docker est constituée de couches en lecture seule empilées les unes sur les autres.

Schéma — Anatomie d'une image Docker

Couche applicative (votre code) Read/Write — modifiable
Dépendances (npm install / pip install) Read Only — cachée
Runtime (Node 20, Python 3.12…) Read Only — cachée
Image de base (Alpine, Debian slim…) Read Only — partagée
Noyau Linux de l'hôte (partagé) Kernel — non embarqué

Les couches basses sont partagées entre conteneurs — seule la couche applicative est unique par conteneur.

💡 À retenir pour un projet SLAM
En 2025, savoir écrire un Dockerfile propre (multi-stage build, image Alpine, .dockerignore) et un docker-compose.yml pour orchestrer une appli + sa base de données est une compétence directement attendue en stage. C'est aussi la base pour comprendre Kubernetes, dont les offres cloud managées (EKS, GKE, AKS) sont omniprésentes en entreprise.
